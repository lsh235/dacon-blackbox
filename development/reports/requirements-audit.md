## 확인된 계약

- 하나의 코드 제출물이 Stage 1, Stage 2, Stage 3 결과를 모두 생성한다.
- 평가기는 `inference.py`의 `predict_stage1`, `predict_stage2`, `predict_stage3`를 호출한다.
- 세 함수는 Stage별로 정해진 컬럼을 가진 `pandas.DataFrame`을 반환한다.
- Stage 2는 이미지 파일명의 원본 프레임 번호를 반환한다.
- Stage 3은 0.1초 단위 `sample_index`를 반환한다.
- 평가 서버는 인터넷을 사용할 수 없고 전체 추론은 60분 이내다.
- 제출 ZIP은 10GB, 압축 해제 후 파일은 32GB 이하여야 한다.
- 기준 장치는 NVIDIA L40S 44.7GiB, 7 vCPU, RAM 60GB, 공유 메모리 30GB다.
- 2차 평가는 모델 개발 보고서와 학습데이터 구성 보고서를 요구한다.

## 공개 예제의 증거 한계

- Stage 1 재녹화 예제는 실제 기기 재촬영이 아닌 파생 예제다.
- Stage 2는 충돌 시점 외 세 과업의 정답 라벨을 제공하지 않는다.
- Stage 3은 실행 확인용 소규모·희소 라벨이다.
- 공개 예제만으로 일반화 성능이나 대회 점수를 주장할 수 없다.

업그레이드 전에 PyTorch 2.4에서 저장한 0 epoch 및 1 epoch 체크포인트를 PyTorch 2.8에서 로드했다. 세 Stage 모두 추론에 성공했고 스모크 CSV는 업그레이드 전 결과와 바이트 단위로 동일했다.

## 미확정 항목

- Stage별 공식 평가 지표와 최종 점수 결합 방식
- 전체 학습데이터의 실제 구성과 라이선스
- 외부 데이터, 합성 데이터, 사전학습 가중치의 허용 범위
- Stage 2 `evasion_space`의 공식 값 정의와 결측 처리
- Stage 3 평가 영상 FPS와 10Hz 표본 변환 규칙
- 추가 모델 파일과 Python 패키지에 대한 상세 제출 규칙

## 다음 결정

1. 공식 평가 자료를 확보하기 전에는 성능 목표치나 최적 모델을 확정하지 않는다.
2. 우선 출력·제출 계약과 데이터 구조 검사를 자동화한다.
3. 공개 예제는 별도 개발 경로로 복사하여 베이스라인 실행 확인에만 사용한다.
4. 요구 버전 환경에서 스모크를 다시 실행하기 전까지 현재 결과를 평가 서버 호환 증거로 표현하지 않는다.

## 공개 Stage 3 영상 시간축 관찰

OpenCV로 공개 예제 5개의 메타데이터를 확인했을 때 각 파일은 약 1,197~1,201프레임이지만 FPS는 약 478~480으로 보고됐다. 반면 라벨의 `frame_index=120`은 `time_seconds=6.0`에 대응하여 20FPS 관계를 보인다. 문서에는 평가 입력이 10Hz라고 적혀 있으므로 세 정보가 서로 일치하지 않는다.

이 관찰만으로 평가 서버의 샘플링 규칙을 결정하지 않는다. 공식 정의를 확보하기 전까지 공개 Stage 3 영상은 구조 스모크에만 사용한다.
